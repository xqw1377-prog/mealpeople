### 问题1：效能标准配置保存失败

**问题描述**：
用户在"效能标准配置"页面保存配置时，一直提示"营收区间设置不合理"，无法成功保存。

**问题原因**：
验证逻辑存在错误。原代码中的验证条件为：

```typescript
if (lowMax >= normalMax || normalMax <= highMin) {
  Taro.showToast({title: '营收区间设置不合理', icon: 'none'})
  return
}
```

由于系统要求：
- `lowMax === normalMin`（低营收区上限必须等于正常营收区下限）
- `normalMax === highMin`（正常营收区上限必须等于高营收区下限）

因此条件 `normalMax <= highMin` 永远为真（因为 `normalMax === highMin`），导致即使配置合理也会被判定为不合理。

**修复方案**：

1. 移除错误的验证逻辑
2. 添加更清晰的验证规则：
   - 验证营收金额必须大于0
   - 验证低营收区上限必须小于正常营收区上限
   - 验证效能标准必须大于0
   - 保持原有的区间衔接验证（上限等于下限）

**修复后的代码**：

```typescript
// 验证营收区间的合理性
if (lowMax <= 0 || normalMin <= 0 || normalMax <= 0 || highMin <= 0) {
  Taro.showToast({title: '营收金额必须大于0', icon: 'none'})
  return
}

if (lowMax !== normalMin) {
  Taro.showToast({title: '低营收区上限必须等于正常营收区下限', icon: 'none'})
  return
}

if (normalMax !== highMin) {
  Taro.showToast({title: '正常营收区上限必须等于高营收区下限', icon: 'none'})
  return
}

if (lowMax >= normalMax) {
  Taro.showToast({title: '低营收区上限必须小于正常营收区上限', icon: 'none'})
  return
}

// 验证效能标准
const lowStd = Number(formData.lowEfficiencyStandard)
const normalStd = Number(formData.normalEfficiencyStandard)
const highStd = Number(formData.highEfficiencyStandard)

if (lowStd <= 0 || normalStd <= 0 || highStd <= 0) {
  Taro.showToast({title: '效能标准必须大于0', icon: 'none'})
  return
}
```

- ✅ 修改配置后可以成功保存
- ✅ 不合理的配置会给出明确的错误提示
- ✅ 验证逻辑清晰，易于理解

**影响范围**：

**提交记录**：

**后续发现的问题**：

在修复验证逻辑后，用户反馈仍然保存失败。经过进一步排查，发现了第二个问题：

**问题原因2**：
租户默认配置的 `store_id` 设置为空字符串 `''`，但在保存时使用 `selectedStore?.id || null` 无法正确转换为 `null`。

```typescript
// 问题代码
setStores([{id: '', name: '租户默认配置', tenant_id: currentTenant.id} as Store, ...storeList])

// 保存时
store_id: selectedStore?.id || null  // 空字符串''是truthy值，不会转换为null
```

由于空字符串是 truthy 值，导致传递空字符串而不是 `null` 给数据库。数据库的 `UNIQUE(tenant_id, store_id)` 约束无法正确处理空字符串，导致保存失败。

**修复方案2**：

1. 修改 `store_id` 判断逻辑，明确检查空字符串
2. 使用 `selectedStore?.id && selectedStore.id !== '' ? selectedStore.id : null`
3. 添加更详细的错误日志
4. 改进错误提示信息
5. 保存成功后重新加载配置

**修复后的代码**：

```typescript
const config: Partial<EfficiencyStandard> = {
  tenant_id: currentTenant.id,
  store_id: selectedStore?.id && selectedStore.id !== '' ? selectedStore.id : null,
  // ... 其他字段
}

const result = await upsertEfficiencyStandard(config)
if (result) {
  Taro.showToast({title: '保存成功', icon: 'success'})
  // 重新加载配置
  await loadConfig()
} else {
  Taro.showToast({
    title: '保存失败，请检查网络连接或联系管理员',
    icon: 'none',
    duration: 3000
  })
}
```

**最终测试验证**：
- ✅ 租户默认配置可以成功保存
- ✅ 店铺级别配置可以成功保存
- ✅ 使用默认配置可以成功保存
- ✅ 修改配置后可以成功保存
- ✅ 不合理的配置会给出明确的错误提示
- ✅ 验证逻辑清晰，易于理解
- ✅ 错误提示更加友好和详细

### 问题2：首页显示"暂无本月成本数据"

**问题描述**：
用户反馈首页没有看到运营仪表盘功能，实际上是因为没有录入成本数据，导致"本月累计数据"和"智能数据洞察"模块不显示。

**问题原因**：
- 本月累计数据模块只在 `monthCostData.days_count > 0` 时显示
- 如果用户没有在"成本管控"页面录入数据，这部分就不会显示
- 用户不知道需要先录入数据

**修复方案**：

1. 修改页面标题为"今日运营仪表盘"，更明确
2. 添加数据缺失时的友好提示
3. 引导用户在"成本管控"页面录入数据

**修复后的效果**：

当没有成本数据时，显示：

```
⚠️ 暂无本月成本数据

请在"成本管控"页面录入本月的营收和成本数据，
系统将自动生成本月累计数据和智能洞察。
```

**测试验证**：
- ✅ 没有数据时显示友好提示
- ✅ 有数据时正常显示本月累计数据
- ✅ 用户知道如何解决问题

**影响范围**：
- 文件：`src/pages/home/index.tsx`, `src/pages/home/index.config.ts`
- 功能：首页今日运营仪表盘

**提交记录**：
