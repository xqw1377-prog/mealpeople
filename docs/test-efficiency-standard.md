# 效能标准配置测试指南

## 测试目的

验证效能标准配置的保存和加载功能是否正常工作。

## 测试前准备

1. 确保已登录系统
2. 确保已选择租户
3. 确保租户下至少有一个店铺
4. 打开浏览器开发者工具的控制台（Console）

## 测试步骤

### 步骤1：配置租户级别效能标准

1. **进入效能配置页面**
   - 从管理中心或导航菜单进入"效能配置"页面

2. **选择租户默认配置**
   - 在"选择配置对象"下拉框中，选择"租户默认配置"

3. **修改配置**
   - 修改任意配置项，例如：
     - 低营收区上限：10000
     - 低营收区效能标准：700
     - 正常营收区上限：18000
     - 正常营收区效能标准：850
     - 高营收区下限：18000
     - 高营收区效能标准：1000

4. **保存配置**
   - 点击"保存配置"按钮
   - 等待保存完成

5. **查看控制台日志**
   - 应该看到以下日志：
     ```
     准备保存效能标准配置: {tenant_id: "xxx", store_id: null, ...}
     查询已存在的配置: null 或 {id: "xxx"}
     插入新配置 或 更新现有配置，ID: xxx
     保存效能标准配置成功: {...}
     ```

6. **验证保存成功**
   - 应该看到"保存成功"的提示

### 步骤2：验证排班规划页面

1. **进入排班规划页面**
   - 从导航菜单进入"排班规划"页面

2. **选择店铺和日期**
   - 选择任意店铺
   - 选择任意日期

3. **查看控制台日志**
   - 应该看到以下日志：
     ```
     loadStandard: 开始加载效能标准 {tenantId: "xxx", storeId: "xxx"}
     getStoreEfficiencyStandard: 查询店铺级别配置 {tenantId: "xxx", storeId: "xxx"}
     getStoreEfficiencyStandard: 店铺级别查询结果 null
     getStoreEfficiencyStandard: 店铺无配置，尝试获取租户级别配置
     getTenantEfficiencyStandard: 查询租户级别配置 {tenantId: "xxx"}
     getTenantEfficiencyStandard: 查询结果 {...}
     loadStandard: 加载结果 {...}
     ```

4. **验证配置加载成功**
   - **不应该**看到"未配置效能标准"的黄色提示框
   - 应该能够看到效能标准相关的信息

5. **输入预估营收**
   - 输入一个营收金额，例如：15000
   - 系统应该自动计算目标人数

6. **验证计算结果**
   - 应该看到：
     - 营收区间：正常营收区
     - 效能标准：850
     - 目标人数：根据营收和效能标准计算得出

### 步骤3：配置店铺级别效能标准（可选）

1. **返回效能配置页面**

2. **选择具体店铺**
   - 在"选择配置对象"下拉框中，选择一个具体的店铺

3. **修改配置**
   - 修改配置项，使其与租户默认配置不同

4. **保存配置**
   - 点击"保存配置"按钮

5. **查看控制台日志**
   - 应该看到`store_id`不为null

6. **返回排班规划页面**
   - 选择刚才配置的店铺
   - 验证加载的是店铺级别的配置（而不是租户级别的配置）

## 预期结果

### 成功标准

✅ 保存配置时显示"保存成功"
✅ 控制台日志显示保存操作成功
✅ 排班规划页面不显示"未配置效能标准"
✅ 排班规划页面能够正确加载配置
✅ 输入营收后能够自动计算目标人数

### 失败标准

❌ 保存配置时显示错误
❌ 控制台日志显示错误信息
❌ 排班规划页面显示"未配置效能标准"
❌ 排班规划页面无法加载配置
❌ 输入营收后无法计算目标人数

## 常见问题排查

### 问题1：保存成功但排班规划页面仍显示"未配置效能标准"

**可能原因**：
1. 租户ID不一致
2. 数据库查询条件不正确
3. RLS策略阻止了查询

**排查步骤**：
1. 查看控制台日志，确认保存时的`tenant_id`
2. 查看控制台日志，确认加载时的`tenant_id`
3. 确认两者是否一致
4. 查看是否有错误日志

### 问题2：控制台显示"查询已存在的配置: null"但实际已有配置

**可能原因**：
1. 查询条件不正确
2. RLS策略阻止了查询

**排查步骤**：
1. 检查`tenant_id`是否正确
2. 检查`store_id`是否正确（租户级别配置应该为null）
3. 检查用户是否有权限访问该租户的数据

### 问题3：保存时显示错误

**可能原因**：
1. 数据验证失败
2. 数据库约束冲突
3. RLS策略阻止了插入/更新

**排查步骤**：
1. 查看控制台的错误详情
2. 检查输入的数据是否符合要求
3. 检查用户是否有权限修改该租户的数据
